# ProfileHub 功能表达与操作流程审视

审视日期：2026-09-17。

范围：当前仓库的导航、概览、成员、角色、权限、应用接入、组织、安全设置、OAuth 同意页与系统设置；浏览器只读查看生产概览、应用列表和个人安全设置。未执行账号修改、授权或删除。以下区分已确认的问题与建议方案，不代表方案已实现。

## 核心判断

当前界面主要按数据对象组织：用户、角色、权限、应用、功能。用户需要先理解数据模型，再自行拼出“让应用接入登录”“给成员授予权限”等任务。品牌仍显示 RBAC 管理系统，首页也没有体现身份服务已经成为核心能力。

改进重点应是操作含义准确、影响范围可见、下一步明确；视觉风格调整排在这些工作之后。

## 1. 优先纠正界面与行为不一致

### 成员移除被写成账号删除

- 用户页确认框写“删除该用户”“不可撤销”，完成后提示“用户已删除”。
- `src/app/api/users/[id]/route.ts` 的 DELETE 实际调用 `removeUserFromTenant`，返回“已从当前租户移除”。
- 建议：改为“移出组织”，确认框显示目标成员、当前组织，以及组织内访问权被移除的影响。补充数据层核查：若移除后没有其他组织归属，现有实现还会删除账号，确认文案必须明确这一条件。全局账号注销应保留在独立流程。
- 还需明确用户编辑的作用域：`src/lib/data-access.ts` 的 `updateUser` 更新共享 User 的姓名、邮箱、密码和状态，而角色分配属于当前组织。不能把二者包装成同一种组织内设置。

### 系统设置看起来生效，实际没有连接到对应行为

- `src/app/(dashboard)/system-config/page.tsx` 保存 `session_timeout`；`src/auth.ts` 的 session.maxAge 固定为 7 天。
- `site_name` 在 TOTP issuer 中有读取，但侧栏品牌来自固定翻译字符串；`site_url` 也不是 OAuth Issuer 的配置来源。
- 页头仍写“全局配置和第三方登录”，当前页面没有第三方登录配置区。
- 建议：逐项标注真实作用域，只展示已接入运行时的配置；需要部署环境变量控制的项目显示实际来源与修改说明。不要先改文案就宣称这些设置已全面生效。

### OIDC 表单暗示尚未支持的能力

- `application-idp-form-page.tsx` 展示客户端 JWKS URI；中文帮助提到 private_key_jwt 和双向 TLS，但当前认证实现不支持这些方式，且两者不应混为一谈。
- scope 中文说明是“与请求有交集”，实际 `validate-authorize.ts` 要求请求 scope 全部属于允许集合；英文说明已经更准确。
- 建议：隐藏尚未使用的 JWKS 输入，或明确标为仅存储、尚不参与验证；更正 scope 的集合关系，中英文同步。

## 2. 把功能入口组织成用户任务

### 导航要区分平台、组织与个人

当前平台总览、组织成员、个人安全与业务权限处于同一层级。“当前租户”“当前组织”混用，“角色”也没有稳定地区分治理角色与业务角色。

建议的信息分组：

- 概览：当前组织状态与下一步。
- 组织：组织资料、成员与邀请、组织管理员及所有权操作。
- 应用与访问：应用接入、功能与权限、业务角色。
- 个人账号：资料、登录方式、安全与恢复。
- 平台管理：仅对平台管理员显示全局组织治理和确属平台范围的设置。

面向用户统一称“组织”，技术文档保留 tenant。治理角色明确叫“组织身份”（负责人、管理员、成员），权限集合叫“业务角色”。分组不改变现有授权规则。

### 首页从数量展示转为可操作概览

`src/components/dashboard/dashboard-view.tsx` 仅展示四项数量。它既没有解释这些数量属于当前组织，也没有帮助新部署完成接入。

建议保留统计，增加基于实际权限和数据状态的入口：“接入应用”“添加成员”“配置业务角色”“保护我的账号”。不要增加尚无数据支撑的安全评分、在线率等装饰指标。

### 组织能力需要可完成的管理流程

`current-organization-view.tsx` 和成员目录当前只读。邀请、所有权移交等能力有服务端接口，当前组织页面缺少操作入口。

建议把只读组织资料与成员管理串起来，按角色和功能开关显示真实可用的操作。邀请需要可见的待接受、已过期、已撤销状态；移交需要说明接收者、确认步骤和对当前负责人的影响。涉及完整新流程，不能只靠修改按钮名称完成。

## 3. 降低关键流程的理解成本

### 应用接入页应交付“可接入的配置”

应用列表的“对外认证 / 管理 OIDC”难以直接说明用途；新建应用后还要自行发现 OIDC 配置入口。长表单把品牌、回调、安全与高级字段并列呈现。

建议围绕“让这个应用使用 ProfileHub 登录”组织：

1. 应用名称、网站地址与客户端类型。
2. 登录回调、退出回调与所需用户信息。
3. 创建凭据，说明 Secret 只显示一次。
4. 展示 Issuer、Discovery、Client ID、回调地址和对应接入示例。

将令牌有效期等放入高级设置。显示“未配置登录 / 已配置登录”，不要在没有实际检查时显示“连接正常”。

### 授权同意页应说明实际共享的信息

`src/app/(flows)/oauth/consent/page.tsx` 主要展示完整回调地址和原始 scope。普通用户无法据此判断授权后果。

建议展示应用、当前登录账号、目标网站域名与逐项说明：身份标识、基本资料、邮箱、允许应用在访问令牌过期后继续获取令牌。技术 scope 保留为次要信息；不能把 offline_access 描述成读取全部资料或永久授权。

### 角色授权要看到上下文与影响

角色编辑将权限平铺为名称和编码。规模增加后，难以区分不同应用的同名权限，也看不出一个角色的总体能力。

建议按应用 → 功能分组，支持搜索、已选汇总和修改预览；明确只读权限与写入权限。角色删除确认应展示实际受影响成员，而非只有“确定删除吗”。

### 安全设置用用户目标命名

生产安全页直接显示 Passkey、MFA、TOTP，并列两种开启流程。恢复流程还有“核选项恢复”“查看服务器日志”等开发者表达。

建议：

- “通行密钥（Passkey）”：说明可用指纹、面容或安全密钥登录，按钮用“添加通行密钥”。
- “两步验证”：先展示状态，再选择验证器或安全密钥。
- “恢复账号访问”：清楚说明会移除哪些登录方式、撤销哪些会话，避免“核选项”等内部用语。
- TOTP 采用添加验证器 → 验证动态码 → 保存恢复码的步骤；保留协议细节给帮助文档。

个人资料同时暴露 image/avatar 两个头像字段，也应在确认兼容性后统一为用户可理解的头像设置。

## 4. 补齐通用状态与反馈

- 用户搜索无结果时仍显示“还没有用户，创建第一个用户”；应区分空组织与没有匹配结果。
- 应用列表和用户列表存在仅图标、无可访问名称的操作按钮；浏览器辅助树中表现为未命名 button。补充明确名称和目标对象。
- 多个管理页只控制导航的读取可见性，新增/编辑按钮未按对应写权限表达可用性；服务端拒绝不能代替界面解释。
- 部分 CRUD 保存流程没有提交中状态，失败只显示通用错误；应保留输入、指出可修复字段，并避免重复提交。
- 生产品牌、浏览器标题仍为“RBAC 管理系统”，侧栏版本固定为 1.0.0。统一品牌，版本只显示真实发布信息。
- 区分正在使用的错误文案和翻译文件中未引用的历史字符串，避免把死代码误判为当前界面能力。

## 建议实施顺序与验收

1. **准确性修正**：成员移除语义、配置生效范围、OIDC 未支持项、scope 说明、品牌与错误文案。验收逐项对照 API 和运行时读取路径。
2. **核心管理任务**：导航分组、组织/业务角色区分、应用接入完成页、权限分组及状态反馈。使用新组织、已有应用、只读成员三类场景验收。
3. **最终用户流程**：授权信息说明、通行密钥/两步验证引导、恢复账号流程，再完善邀请和移交的管理界面。使用浏览器完成流程，覆盖取消与错误分支。

## 实施记录（本地）

以上为初始审查记录。后续已完成以下改动：

- 导航按组织、应用接入、个人账号和平台分组，统一 ProfileHub 品牌；概览增加按权限显示的任务入口。
- 成员页区分组织身份和业务角色，说明共享账号字段的影响；新增、编辑、删除依据对应权限表达可用性，补充提交状态、操作名称和搜索空状态。
- 保留既有成员移除行为并明确告知：仍属于其他组织时保留账号；移除最后一个组织关系时删除账号。未擅自改变数据生命周期。
- 角色权限可搜索，并展示应用和功能上下文、已选数量；删除前展示关联成员数量。
- 运行配置页展示实际 Issuer、会话有效期和 TOTP 名称来源，不再提供不会影响认证运行时的保存操作。
- 应用接入页交付可复制的 Issuer、Discovery、Client ID 和回调地址；令牌有效期折叠到高级设置；移除未被运行时使用的 JWKS 输入。
- 授权页展示账号、目标域名、用户信息用途与应用链接；保留协议 scope 和完整回调供检查。
- 安全设置采用通行密钥、两步验证、恢复账号访问等用户表述；补充验证器步骤，兼容头像覆盖项收进详情。
- 当前组织页接入邀请码创建、状态查看、接受邀请，以及负责人发起和接收人确认移交；无组织账号也可接受邀请。入口遵循功能开关和权限。
- 所有权移交确认使用事务，校验当前负责人和成员身份，成功后使其他待处理请求失效；列表仅向负责人和对应接收人提供记录。

### 已验证与边界

- 真实临时数据库回归覆盖邀请邮箱绑定、重复使用、组织隔离、移交访问限制、旧请求失效和成员移除后账号生命周期。
- 使用独立本地数据库进行浏览器检查；未操作生产账号或部署本轮改动。
- 邀请码和移交通知仍需手动分享，不自动发邮件；邀请撤销接口尚未实现，因此没有展示撤销按钮或虚构已撤销状态。
- 验证器提供现有手动添加方式，尚未新增二维码。角色权限目前展示层级上下文，尚未增加授权差异预览。
- 本轮没有变更存量账号生命周期、数据库结构或生产环境配置。
